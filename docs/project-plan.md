## 1. 과제의 필요성

### 1) 배경 및 문제 인식

인터넷은 학습, 과제 수행, 프로그램 개발, 논문 및 자료 조사와 같은 작업에서 주요 정보 탐색 수단으로 사용된다. 사용자는 일반적으로 `캡스톤 프로젝트에 사용할 데이터셋 찾기`, `Spring Boot에서 JWT 인증 구현 방법 조사하기`와 같이 구체적인 목적을 가지고 탐색을 시작한다.

그러나 웹 정보 탐색은 하나의 페이지에서 끝나지 않는다. 검색 결과에서 여러 자료를 확인하고 문서 내부의 링크를 따라 이동하거나 여러 탭을 열면서 탐색 범위가 확장된다. 이러한 행동 자체는 정상적인 정보 탐색이지만 탐색이 반복되면서 최초 작업 목표와 관계가 낮은 내용으로 점진적으로 이동할 수 있다.

예를 들어 `공개 인공지능 데이터셋 찾기`라는 목표에서 데이터셋 설명, 관련 논문, 논문에서 사용된 다른 데이터셋으로 이동하는 것은 정상적인 탐색이다. 반면 관련 인물, 인터뷰, 연예 기사 등으로 연속적으로 이동하면 각 페이지가 직전 페이지와 관련되어 있더라도 전체 흐름은 최초 목표에서 멀어질 수 있다.

Rosen, Carrier와 Cheever(2013)는 학습 중 발생하는 미디어 기반 task-switching 행동을 다루었으며, Wu와 Xie(2018)는 온라인 검색 과정에서 과제와 관계없는 탐색 행동을 연구하였다. 본 프로젝트는 이러한 문제를 바탕으로 **명확한 목적을 가지고 시작한 웹 탐색이 최초 목표에서 점진적으로 이탈하는 상황**을 분석 대상으로 설정한다.

본 프로젝트는 사용자의 집중력 수준을 평가하거나 ADHD와 같은 질환을 진단하는 시스템이 아니다. 사용자가 명시적으로 시작한 목적 지향적 웹 정보 탐색 세션에서 최초 작업 목표와 최근 탐색 흐름의 관계를 분석하는 것으로 범위를 한정한다.

### 2) 문제 정의 및 범위

본 프로젝트에서는 하나의 페이지가 최초 목표와 관련성이 낮다는 이유만으로 목표 이탈로 판단하지 않는다. 실제 정보 탐색에서는 배경지식 확인이나 비교 자료 탐색을 위해 일시적으로 직접적인 관련성이 낮은 페이지를 방문할 수 있기 때문이다.

따라서 목표 이탈 판단 단위를 단일 페이지가 아닌 최근 **5개의 유효 Page Visit으로 구성된 탐색 구간(window)**으로 정의하며, 새로운 페이지가 추가될 때마다 한 페이지씩 이동하는 sliding window 방식을 사용한다.

| 상태 | 정의 | 시스템 동작 |
| --- | --- | --- |
| `NORMAL` | 최초 목표를 직접 수행하고 있거나 목표 달성을 위해 합리적으로 필요한 탐색 상태 | 알림하지 않음 |
| `TRANSITION` | 최초 목표와의 관련성이 감소하고 있으나 명확한 이탈로 판단하기 어려운 상태 | 추가 탐색 관찰 |
| `DRIFT` | 최근 탐색 흐름이 최초 목표와 명확하게 관계없는 방향으로 지속적으로 이동한 상태 | 최초 작업 목표 재제시 |

`TRANSITION`을 별도로 정의하여 목표 이탈을 특정 페이지에서 갑자기 발생하는 사건이 아니라 `NORMAL → TRANSITION → DRIFT`와 같이 점진적으로 변화할 수 있는 탐색 흐름으로 다룬다.

성능 보장 범위는 **Windows 11 기반 Google Chrome Desktop Stable에서 수행되는 한국어·영어 기반 목적 지향적 정보 탐색**으로 한정한다. 최종 평가에서는 실제 시험에 사용한 Chrome 버전을 기록한다.

지원 대상은 다음과 같다.

- 학습·정보 탐색
- 과제 조사
- 개발·기술 조사
- 논문·자료 조사

지나치게 포괄적인 목표, 자유 탐색, 보고서 작성이나 코딩 자체처럼 웹 정보 탐색이 주된 작업이 아닌 경우는 제외한다.

분석 대상은 공개 HTML 문서, 검색 결과 페이지, 기술 문서, 블로그·기사, 공개 논문 및 자료 소개 페이지이다. 검색어 추출은 Google Search와 Naver Search를 대상으로 한다.

`chrome://`, `chrome-extension://`, 로그인·회원가입·결제·금융·개인정보 입력 중심 페이지, Chrome 기본 PDF Viewer, 영상·음성 콘텐츠 자체는 초기 분석 대상에서 제외한다.

### 3) 기존 해결방안 분석 및 차별성

StayFocusd와 Freedom과 같은 기존 서비스는 사용자가 방해가 된다고 판단한 사이트를 차단하거나 이용시간을 제한하는 방식을 제공한다. 그러나 동일한 사이트라도 사용자의 현재 목표에 따라 정상적인 작업 공간이 될 수도 있고 목표 이탈 공간이 될 수도 있다.

| 구분 | 사이트·시간 기반 방식 | 본 프로젝트 |
| --- | --- | --- |
| 판단 기준 | 사이트 주소, 이용시간 | 최초 목표와 실제 탐색 흐름 |
| 페이지 내용 | 제한적으로 고려 | 의미적 관련성 분석 |
| 연속적 탐색 | 주요 판단 기준이 아님 | 최근 여러 페이지의 순서와 변화 분석 |
| 합리적 우회 | 사이트가 차단 대상이면 제한될 수 있음 | 이전 탐색 맥락을 함께 고려 |
| 점진적 이탈 | 별도 상태 정의 없음 | NORMAL / TRANSITION / DRIFT |
| 개입 방법 | 접속 차단 또는 제한 | 최초 목표 재제시 |
| 사용자 선택 | 시스템 제한 중심 | 사용자가 계속 탐색할지 직접 결정 |

또한 본 프로젝트에서는 일정 시간마다 목표를 표시하는 **고정 주기 목표 알림**을 비교 기준으로 사용한다. 이를 통해 단순히 AI를 사용한다는 점이 아니라 실제 탐색 상황을 바탕으로 알림 시점을 선택하는 것이 불필요한 개입을 줄이고 더 적절한 시점에 목표를 재인식시키는지를 검증한다.

### 4) 핵심 가설 및 도출 근거

첫째, **최초 작업 목표와 페이지 내용의 의미적 관련성은 목표 이탈 판단에 활용할 수 있다**는 가설이다.

둘째, **단일 페이지 관련성보다 최근 탐색 흐름을 함께 분석하면 정상적인 우회 탐색과 실제 목표 이탈을 더 잘 구분할 수 있다**는 가설이다.

이를 검증하기 위해 다음 세 가지 특징 구성을 비교한다.

1. 의미적 관련성만 사용
2. 의미적 관련성 + 최근 탐색 맥락
3. 의미적 관련성 + 최근 탐색 맥락 + 행동 정보

셋째, 실제 목표 이탈 시 최초 목표를 다시 제시하면 사용자가 원래 작업을 재인식하는 데 도움을 줄 수 있다는 가설이다. Hodgetts와 Jones(2006)는 중단된 작업과 관련된 맥락 단서가 작업 목표 회복에 도움을 줄 가능성을 제시하였다.

넷째, **AI 기반 알림은 고정 주기 알림보다 불필요한 개입을 줄이면서 적절한 시점에 목표를 재제시할 수 있다**는 가설이다.

## 2. 과제의 목표 및 내용

### 1) 최종 목표 및 정량적 성과지표

본 프로젝트의 최종 목표는 **웹 탐색 과정에서 발생하는 점진적 목표 이탈을 자동으로 탐지하고 필요한 시점에 최초 작업 목표를 다시 제시하는 실제 동작 가능한 시스템을 구현하며 그 효과를 정량적으로 검증하는 것**이다.

모델 평가는 최근 5개 유효 Page Visit으로 구성된 탐색 구간을 기준으로 수행하며, NORMAL, TRANSITION, DRIFT 세 클래스의 성능을 동일하게 평가하기 위해 Macro F1을 주요 지표로 사용한다.

| 구분 | 성과지표 | 목표 | 설정 이유 |
| --- | --- | --- | --- |
| 모델 | Macro F1 | 0.80 이상 | 세 클래스 전체에 대한 내부 성능 합격 기준 |
| 모델 | 클래스별 F1 | 각 0.70 이상 | 특정 클래스의 낮은 성능이 Macro F1에 가려지는 것을 방지 |
| 모델 | DRIFT Recall | 0.80 이상 | 실제 목표 이탈의 대부분을 탐지하는 것을 목표로 설정 |
| 모델 | DRIFT 오알림률 | 10% 이하 | NORMAL·TRANSITION 상태에서 반복적인 사용자 방해를 줄이기 위한 기준 |
| 모델 | 실제 DRIFT 발생 후 2개 탐색 구간 이내 탐지율 | 80% 이상 | 목표 이탈 후 지나치게 늦게 알림하는 문제를 방지 |
| 시스템 | AI 분석 전체 p95 응답시간 | 5초 이하 | 초기 RTX 4060 Ti PoC 결과를 바탕으로 설정한 시스템 목표 |
| 데이터 | 독립 탐색 세션 | 160개 이상 | 목표·사용자별 탐색 패턴 확보 |
| 데이터 | 파생된 5페이지 탐색 구간 | 최소 1,200개 | 분류기 학습 및 평가 단위 확보 |
| 사용자 평가 | 평가 참여자 | 12명 | 두 알림 조건을 같은 사용자가 비교 평가 |
| 사용자 평가 | AI 알림 시점 적절성 | 5점 척도 평균 4.0 이상 | 5점 척도에서 ‘적절하다’ 수준을 목표로 설정 |

각 기준은 본 프로젝트에서 모델과 시스템의 완성도를 판단하기 위해 설정한 공학적 목표값이다.

클래스별 Precision과 Recall을 이용해 F1을 계산하고, `NORMAL`, `TRANSITION`, `DRIFT` 세 클래스의 F1 평균을 Macro F1으로 산출한다.

`MacroF1 = (F1_NORMAL + F1_TRANSITION + F1_DRIFT) / 3`

DRIFT 오알림률은 실제 상태가 NORMAL 또는 TRANSITION임에도 DRIFT로 분류된 비율로 정의한다.

`FalseAlertRate = #(y ≠ DRIFT and ŷ = DRIFT) / #(y ≠ DRIFT)`

탐지 지연은 실제 DRIFT가 처음 발생한 탐색 구간과 시스템이 처음 DRIFT를 예측한 탐색 구간의 차이로 측정하며 실제 DRIFT 발생 후 2개 탐색 구간 이내 탐지 여부를 함께 평가한다.

AI 알림 시점 적절성은 사용자 평가 종료 후 **‘알림이 적절한 시점에 제공되었다’** 문항을 5점 Likert 척도로 평가하고 평균을 산출한다.

AI 분석 응답시간은 Chrome Extension이 분석 요청을 전송한 시점부터 최종 분류 결과를 수신한 시점까지 측정한다. 최초 모델 다운로드 및 초기 로딩 시간은 제외하고 평균, 중앙값, p95, 최대 응답시간을 기록한다.

### 2) 세부 목표 및 개발 범위

데이터 수집은 사용자가 명시적으로 작업 세션을 시작한 시점부터 종료한 시점까지만 수행한다.

| 수집 정보 | 수집하지 않는 정보 |
| --- | --- |
| 방문 순서, 정규화된 URL, 도메인, 페이지 제목, 제한된 본문, 검색어, 방문 시각, 활성 체류시간, 탭 전환 횟수, 검색 결과 페이지 여부 | 비밀번호, 폼 입력값, 쿠키, 인증 토큰, LocalStorage·SessionStorage, 클립보드, 전체 키입력, 마우스 좌표, 다운로드 파일 내용, 전체 Chrome 방문기록 |

URL의 query parameter와 fragment는 기본적으로 제거한다. 페이지 본문은 script, style, 광고, 숨겨진 요소, 폼 입력값 등을 제외하고 화면에 표시되는 텍스트 중 최대 약 5,000자를 사용한다.

활성 체류시간은 해당 페이지가 활성 탭이고 브라우저 창이 활성 상태였던 시간만 누적한다.

데이터 구축 전 참여자에게 수집 항목과 목적을 안내하고 동의를 받으며 이름이나 학번 대신 `P001`, `P002`와 같은 익명 식별자를 사용한다.

### 3) 과제 내용

전체 시스템은 Chrome Extension, Spring Boot 백엔드, Python AI Service, 데이터 저장 영역으로 구성한다.

**목표 입력 → 세션 시작 → 탐색 정보 수집 → Spring Boot 전달 → 의미적 관련성 분석 → 탐색 맥락 분석 → 행동 특징 결합 → NORMAL/TRANSITION/DRIFT 분류 → DRIFT 시 최초 목표 재제시 → 사용자 선택 기록**

AI 분석은 다음 세 역할로 구성한다.

| 구성 | 입력 | 출력 |
| --- | --- | --- |
| EmbeddingModel | 목표, 페이지 제목, 제한된 본문 | semantic relevance |
| ContextModel | 목표, 최근 5개 페이지, 검색어, 방문 순서, relevance | goalRelevance, detourJustification, driftDegree, contextState |
| DriftClassifier | 의미적·맥락적·행동 특징 | P(NORMAL), P(TRANSITION), P(DRIFT) |

`goalRelevance`, `detourJustification`, `driftDegree`는 0.0~1.0 범위의 값이며 `contextState`는 NORMAL, TRANSITION, DRIFT 중 하나이다.

구조화된 출력 검증에 실패하면 1회 재시도하며, 재시도에도 실패하면 해당 분석을 실패로 처리하고 사용자 알림을 발생시키지 않는다.

최종 분류 시 `P(DRIFT) ≥ τ`이면 DRIFT로 판정하고, 그렇지 않으면 `P(NORMAL)`과 `P(TRANSITION)` 중 높은 값을 선택한다. 임계값 `τ`는 Validation 데이터에서 결정하며 Test 결과를 이용해 재조정하지 않는다.

최종 분류기는 Logistic Regression, Random Forest, XGBoost를 비교하고 Macro F1, 클래스별 F1, DRIFT Recall, 오알림률, Train-Validation 성능 차이, 추론시간을 종합하여 선정한다.

### 3) 데이터 확보 및 처리 계획

데이터는 다음 계층으로 구성한다.

**Task Goal → Session → Page Visit → Window → Label**

| 항목 | 목표 |
| --- | --- |
| 기본 탐색 목표 | 20개 |
| 데이터 구축 참여자 | 10명 |
| 참여자당 세션 | 16개 |
| 독립 탐색 세션 | 160개 이상 |
| 세션당 유효 페이지 | 약 10~15개 |
| 탐색 구간 크기 | 최근 5 Page Visit |
| Sliding stride | 1 |
| 파생된 labeled window | 최소 1,200개, 권장 1,500개 이상 |

20개의 목표는 학습·정보 탐색, 과제 조사, 개발·기술 조사, 논문·자료 조사 네 영역에 각각 5개씩 배정한다. 각 목표는 약 8개의 독립 세션을 확보하여 총 160개 이상의 세션을 구축한다.

각 목표에는 다음 네 종류의 수행 조건을 적용한다.

| 수행 조건 | 설명 |
| --- | --- |
| 목표 유지 | 처음부터 끝까지 작업 목표와 관련된 탐색 수행 |
| 합리적 우회 | 필요한 배경·비교 자료를 확인한 뒤 목표 탐색을 지속 |
| 점진적 이탈 | 목표 관련 탐색에서 시작하여 점차 다른 주제로 이동 |
| 명확한 이탈 | 일정한 목표 탐색 이후 관계없는 주제로 이동 |

참여자에게 NORMAL, TRANSITION, DRIFT 라벨은 알려주지 않고 수행 조건만 제공한다.

동일 참여자가 동일 목표를 반복하지 않도록 배정하며 참여자 식별자는 모델 입력 특징으로 사용하지 않는다.

한 세션은 약 10~15개의 유효 Page Visit이 확보되거나 과제가 완료되면 종료한다. 최대 탐색시간은 파일럿에서 확정한 뒤 동일한 기준을 적용한다.

최근 5개 Page Visit에 stride 1 sliding window를 적용한다. n개의 Page Visit이 존재하는 경우 `n-4`개의 탐색 구간이 생성되므로 평균 12페이지 세션에서는 약 8개, 160세션에서는 약 1,280개의 탐색 구간이 생성된다.

NORMAL, TRANSITION, DRIFT 각각 최소 300개 이상의 탐색 구간 확보를 목표로 하며 부족한 클래스는 복제보다 실제 탐색 세션을 추가 수집한다.

운영 데이터는 관계형 DB에 저장하고 학습용 탐색 기록은 JSONL, 분류기용 수치 특징은 표 형식으로 구성한다.

#### 라벨링 및 데이터 분할

팀원 3명이 각 탐색 구간을 독립적으로 NORMAL, TRANSITION, DRIFT 중 하나로 라벨링한다. 2명 이상이 같은 상태로 판단하면 다수결로 확정하고 세 명의 판단이 모두 다르면 공동 검토한다.

평가자 간 일치도는 Fleiss' κ로 측정한다.

Train/Validation/Test는 window 단위로 무작위 분할하지 않고 **작업 목표 단위**로 분리한다.

- Train: 12개 목표, 약 96세션
- Validation: 4개 목표, 약 32세션
- Test: 4개 목표, 약 32세션

각 집합에 네 작업 영역이 모두 포함되도록 하여 동일 목표에서 파생된 유사한 탐색 구간이 학습과 평가 데이터에 동시에 포함되는 것을 방지한다.

### 4) 모델·알고리즘 및 검증 계획

다음 세 가지 특징 구성을 비교하여 탐색 맥락과 행동 정보의 추가 기여도를 확인한다.

| 실험 | 사용 특징 |
| --- | --- |
| A. Embedding | 의미적 관련성만 사용 |
| B. Embedding + Context | 의미적 관련성 + 최근 탐색 맥락 |
| C. Embedding + Context + Behavior | 의미적 관련성 + 최근 탐색 맥락 + 행동 정보 |

Context Model은 Qwen3-4B FP16과 Qwen3-8B 4-bit를 Validation 데이터에서 비교하며, Test 데이터는 최종 모델 및 설정 확정 이후 일반화 성능 평가에만 사용한다.

과적합을 줄이기 위해 다음 원칙을 적용한다.

- 목표 단위 Train/Validation/Test 분리
- Validation 기반 hyperparameter 및 DRIFT threshold 결정
- Train-Validation 성능 차이 확인
- Test set은 최종 모델 결정 이후 한 번 평가
- Test 결과를 이용한 model parameter 및 threshold 재조정 금지

실제 시스템에서는 유효 Page Visit이 5개 이상 누적된 이후 새로운 페이지가 추가될 때마다 최근 5개 Page Visit을 분석한다.

응답시간 목표를 만족하지 못할 경우 embedding 관련성 변화를 이용해 Context Model 호출 횟수를 줄이는 최적화를 검토한다.

### 1) 최종 산출물

1. React 기반 Chrome Extension

4. 기본 20개 목표, 160개 이상의 독립 탐색 세션, 최소 1,200개 탐색 구간으로 구성된 데이터셋
5. 모델·특징 비교 및 사용자 비교 평가 결과
6. GitHub 기반 개발·협업 기록

최종 결과는 AI 모델 개발에 그치지 않고 사용자가 목표를 입력하고 웹을 탐색하면 탐색 정보를 수집하고 목표 이탈을 판단하여 필요한 경우 최초 목표를 다시 표시하는 전체 과정을 실제 시스템에서 시연하는 것을 목표로 한다.

### 2) 활용 방안

본 시스템은 다음과 같은 목적 지향적 정보 탐색에 활용할 수 있다.

- 대학생의 학습 및 과제 자료 조사
- 개발자의 기술 조사 및 문제 해결 자료 검색
- 논문·데이터셋 탐색
- 일반적인 목적 지향적 정보 조사

많은 탭을 사용하거나 여러 웹페이지를 이동하는 행동 자체는 목표 이탈로 판단하지 않고 최초 목표와 실제 탐색 흐름의 관계를 분석한다.

향후에는 사용자가 목표 재제시 이후 선택한 행동을 누적하여 사용자별 알림 기준을 조정하는 개인화 기능으로 확장할 수 있으나 개인화 모델은 현재 개발 범위에서 제외한다.

### 3) 기대 효과

첫째, 사이트를 일괄 차단하지 않으면서 현재 탐색이 최초 작업 목표에서 지속적으로 멀어지고 있는지를 확인할 수 있다.

둘째, 의미적 관련성, 최근 탐색 맥락, 행동 정보가 목표 이탈 판단 성능에 각각 어느 정도 기여하는지를 ablation 실험으로 확인할 수 있다.

셋째, NORMAL, TRANSITION, DRIFT의 3단계 상태와 탐지 지연 지표를 이용해 목표 이탈을 점진적인 탐색 변화로 분석할 수 있다.

넷째, AI 기반 알림을 고정 주기 알림과 비교하여 **탐색 흐름에 따라 알림 시점을 결정하는 것의 추가 가치**를 검증할 수 있다.

최종 사용자 평가는 12명을 대상으로 두 알림 방식을 모두 경험하는 within-subject 방식으로 진행한다. 순서 효과를 줄이기 위해 절반은 `AI → 고정 주기`, 나머지는 `고정 주기 → AI` 순서로 수행하며 두 조건에는 난이도와 영역이 유사한 서로 다른 탐색 목표를 교차 배정한다.

평가 항목은 다음과 같다.

- 알림 시점 적절성
- 불필요한 알림 수
- 사용자 체감 작업 방해 정도
- 목표 복귀 선택률
- 세션당 알림 횟수

고정 주기 알림 간격은 **최종 사용자 평가 전 사전 파일럿에서 AI 방식과 유사한 평균 세션당 알림 횟수가 발생하도록 설정하고, 최종 사용자 평가가 시작된 이후에는 변경하지 않는다.**

실제 DRIFT 상태에서 사용자가 `원래 작업으로 복귀`를 선택한 비율을 목표 복귀 선택률로 정의하여 두 방식의 차이를 비교한다.
