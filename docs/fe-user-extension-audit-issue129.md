## v1·v2 실행 흐름과 재사용 경계

- **v1**은 팝업 목표 → `startSession()` → POST 세션 → ACK 후 `Collector` 시작 → 허용 사이트 content 메시지 → Visit POST 및 행동 PATCH → 종료 drain이다. v1은 활성 체류 1초부터 유효 Visit 후보가 되고, BE는 5개씩 한 칸 이동한 Window를 만든다. legacy 분석은 마지막 Visit의 활성 체류 10초를 기준으로 요청하며, 종료 때 남은 Window도 요청한다. FE는 목표와 수집·세션 상태를 보여주며 v1 분석 조회·표시·선택 UI는 연결하지 않는다. [팝업](../fe/src/popup/index.tsx#L103) · [Worker](../fe/src/background/index.ts#L364) · [v1 Window](../be/src/main/java/com/focusrecovery/domain/window/service/AnalysisWindowService.java#L21) · [v1 유효화](../fe/src/background/collector.ts#L63) · [legacy 분석 요청](../be/src/main/java/com/focusrecovery/domain/analysis/service/AnalysisRequestService.java#L56)
- **v2**는 `installV2Browser()` → 서버 인증/동의·정책 → 배정 또는 고정 합성 목표 → `V2Runtime.start()`/IDB → content 관측 → `V2Collector` → v2 Visit/행동 계약 → BE watermark → AI 3-Visit 구성(size 3, stride 1)과 관련성 → BE 최종 상태 → 화면에서 조회한다. 수집·전송은 AI 응답을 기다리지 않는다. `individual-local`의 RAW_ONLY는 실제로 dispatch를 끄며, `real-collection`의 dispatch 설정은 해당 프로필과 승인 정책의 적용이 전제다. [설치와 시작](../fe/src/v2/browser.ts#L21) · [Runtime](../fe/src/v2/runtime.ts#L164) · [Collector](../fe/src/v2/collector.ts) · [BE 방문 분기](../be/src/main/java/com/focusrecovery/domain/visit/service/PageVisitService.java#L96) · [구성 처리](../be/src/main/java/com/focusrecovery/domain/composition/service/CompositionService.java) · [local](../be/src/main/resources/application-individual-local.properties) · [real](../be/src/main/resources/application-real-collection.properties)
- **재사용**은 v2 저장/Runtime/수집 계약·권한 검사·정제·동일 세션 ACK 복구를 중심으로 한다. 두 FE는 이미 `VisitDelivery`, `BehaviorDelivery`, `SessionEndDelivery`, serial executor, DOM/검색·URL 정제, API helper를 공유한다. v1 팝업은 목표 입력·종료 상태 표현을 참고할 수 있다. v1 저장/방문 규격과 v2 상태·수집 경로를 혼합하면 5개/3개 Window, 방문 용인 조건, wire/version과 기존 checkpoint가 함께 흔들린다. [공유 전송기](../fe/src/background/visit-delivery.ts) · [행동 전송기](../fe/src/background/behavior-delivery.ts) · [종료 전송기](../fe/src/background/session-end.ts) · [v2 저장소](../fe/src/v2/repository.ts)
